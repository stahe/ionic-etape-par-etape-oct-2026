    9. Dialoguer avec le serveur

    Le serveur JSON [RdvMedecins] doit maintenant être lancé (port 8080), comme expliqué au chapitre précédent, de préférence en mode test du captcha ([CAPTCHA_TEST=test]), qui permet de répondre « test » à n'importe quelle image.

    Les exemples 22 à 25 partagent quelques fichiers, rangés dans le dossier [src/app/commun/] du projet : l'adresse du serveur ([config.ts]), les types des réponses ([types.ts]), la classe des erreurs ([erreur-api.ts]), le service des requêtes ([api.ts]) et une barre de connexion ([barre-connexion.ts]). Ils sont présentés au fil des exemples, là où ils deviennent utiles.

    9.1.1. Où est le serveur ?

    Pour un client web servi par le serveur lui-même, la question ne se pose pas : les requêtes partent vers la même origine que la page, avec une adresse relative ([/api/captcha]). Une application installée sur un téléphone n'a pas d'origine utilisable : sa page est servie par [Capacitor] lui-même, depuis https://localhost. Il faut lui donner l'adresse complète du serveur, et cette adresse dépend de l'endroit où tourne l'application :

    // =========================================================================
// src/app/commun/config.ts - OÙ est le serveur JSON ?
// -------------------------------------------------------------------------
// La question ne se pose pas pour une application web servie par le
// serveur lui-même : les requêtes partent vers la MÊME origine que la page
// (une adresse relative, /api/...). Mais une application MOBILE n'a pas
// d'origine utilisable (sur Android, la page est servie par Capacitor
// depuis https://localhost) : il faut lui donner l'adresse complète du serveur.
//   - en développement web (ng serve), le serveur de développement
//     d'Angular transmet les requêtes /api au serveur JSON (fichier
//     proxy.conf.json) : une adresse relative suffit ;
//   - l'émulateur Android voit l'ordinateur qui le fait tourner à
//     l'adresse 10.0.2.2 (localhost, pour lui, c'est l'émulateur lui-même) ;
//   - un vrai téléphone, relié au même réseau Wi-Fi que l'ordinateur, doit
//     utiliser l'adresse de l'ordinateur sur ce réseau (192.168.1.20...) :
//     on la donne à la construction de l'application :
//         ng build --define "SERVEUR='http://192.168.1.20:8080'"
//     ou bien on modifie la constante serveurAndroid ci-dessous.
// =========================================================================

import { Capacitor } from '@capacitor/core';

// l'adresse du serveur pour l'application Android, quand rien d'autre
// n'est imposé : celle de l'ordinateur, vue de l'émulateur
const serveurAndroid = 'http://10.0.2.2:8080';

// la valeur donnée par --define "SERVEUR='...'" à la construction
// (ng build, ng serve). L'option remplace, dans le code compilé, le mot
// SERVEUR par la valeur donnée. Sans elle, SERVEUR n'existe pas : typeof
// permet de le vérifier sans provoquer d'erreur
declare const SERVEUR: string | undefined;
const serveurImpose = typeof SERVEUR === 'string' ? SERVEUR : '';

export const config = {
  // Capacitor.isNativePlatform() : vrai dans l'application Android (ou iOS),
  // faux dans un navigateur ; Capacitor.getPlatform() : 'android', 'ios' ou 'web'
  urlServeur:
    serveurImpose !== ''
      ? serveurImpose
      : !Capacitor.isNativePlatform()
        ? '' // le web : même origine, adresses relatives
        : Capacitor.getPlatform() === 'android'
          ? serveurAndroid
          : 'http://localhost:8080',
};
    • ligne 21 : [Capacitor], l'objet de [@capacitor/core] qui renseigne sur la plate-forme où tourne l'application. Il est utilisable partout, y compris dans un navigateur ;
    • ligne 25 : l'adresse par défaut sur [Android]. L'émulateur est une machine à part entière, avec son propre réseau : pour lui, [localhost], c'est l'émulateur lui-même. L'adresse spéciale [10.0.2.2] désigne l'ordinateur qui le fait tourner ;
    • lignes 31-32 : une adresse imposée à la construction de l'application, par l'option [--define] d'[Angular] : [ng build --define "SERVEUR='http://192.168.1.20:8080'"]. La compilation remplace, dans le code, l'identifiant [SERVEUR] par la valeur donnée (une chaîne, d'où les apostrophes). Sans l'option, [SERVEUR] n'existe pas : [declare const] annonce au compilateur [TypeScript] un identifiant qu'il ne voit pas déclaré, et [typeof SERVEUR] permet de tester son existence sans provoquer d'erreur. C'est le pendant exact de [--dart-define] et [String.fromEnvironment] en [Flutter] ;
    • lignes 34-45 : sinon, une adresse selon la plate-forme. [Capacitor.isNativePlatform()] est vrai dans l'application [Android] (ou [iOS]), faux dans un navigateur ; [Capacitor.getPlatform()] rend 'android', 'ios' ou 'web' :
    • dans le navigateur (ligne 41) : une adresse relative (''), donc la même origine que l'application ;
    • sur [Android] (ligne 43) : l'adresse de la ligne 25 ;
    • ailleurs (ligne 44, [iOS], que ce cours n'aborde pas) : [localhost].

    Un vrai téléphone, relié au même réseau Wi-Fi que l'ordinateur du serveur, doit utiliser l'adresse de l'ordinateur sur ce réseau (la commande [ipconfig] de [Windows] la donne) : on la passe par [--define] à la construction, ou l'on modifie la constante de la ligne 25. Il faut aussi que le pare-feu de l'ordinateur laisse passer les connexions entrantes sur le port 8080.

    // =========================================================================
// capacitor.config.ts - la configuration de Capacitor
// -------------------------------------------------------------------------
// Capacitor transforme l'application web (le dossier produit par ng build)
// en application Android : il l'emballe dans un projet Android Studio
// (dossier android/), où elle est affichée par une "WebView", le moteur du
// navigateur Chrome du téléphone. Commandes (cf. exemple 01, « Exécution ») :
//     npx cap add android       (une seule fois : crée le dossier android/)
//     ng build                  (fabrique l'application web)
//     npx cap sync android      (la copie dans le projet Android)
//     npx cap run android       (la lance sur un émulateur ou un téléphone)
// =========================================================================

import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  // l'identifiant unique de l'application sur le téléphone (et sur le Play Store)
  appId: 'fr.stahe.exemples',
  // le nom affiché sous l'icône
  appName: 'Exemples Ionic',
  // le dossier de l'application web compilée (ng build)
  webDir: 'dist/exemples_ionic/browser',
  server: {
    // autorise les requêtes HTTP non chiffrées (http://10.0.2.2:8080) vers
    // le serveur JSON de développement (exemples 22 à 25)
    cleartext: true,
  },
  plugins: {
    // CapacitorHttp : les requêtes HTTP de l'application ne sont plus faites
    // par la WebView mais par le code natif d'Android. Conséquences (cf.
    // exemples 22 et 23) : pas de contrôle CORS (le serveur JSON n'a rien à
    // autoriser), et les cookies (celui du jeton d'authentification) sont
    // rangés par Android et renvoyés automatiquement
    CapacitorHttp: {
      enabled: true,
    },
  },
};

export default config;
    • lignes 23-27 : [server.cleartext: true]. Depuis la version 9 d'[Android], une application n'a le droit de communiquer qu'en HTTPS. Notre serveur de développement parle HTTP : on l'autorise. La commande [npx cap sync android] reporte ce réglage dans le projet [Android] (l'attribut [android:usesCleartextTraffic="true"], ajouté au manifeste que [Capacitor] fusionne avec celui de l'application). En production, le serveur serait en HTTPS et ce réglage disparaîtrait ;
    • lignes 28-37 : le greffon [CapacitorHttp]. Les requêtes HTTP de l'application (celles du client HTTP d'[Angular], comme celles de [fetch]) ne sont plus envoyées par la WebView mais par le code natif d'[Android]. Pour un navigateur, l'application (https://localhost) et le serveur (http://10.0.2.2:8080) auraient deux origines différentes : il exigerait du serveur une autorisation CORS qu'il ne donne pas, et refuserait de joindre le cookie du jeton. Le code natif n'a pas ces règles. Le code [TypeScript] de l'application, lui, ne change pas : c'est [Capacitor] qui détourne les requêtes.

    9.1.3. Et dans le navigateur ?

    Pendant le développement, l'application tourne dans le navigateur de l'ordinateur : [ng serve] la sert sur le port 8100, le serveur JSON est sur le port 8080. Deux origines, là encore, et [CapacitorHttp] n'agit pas dans un navigateur. La solution est un proxy, déclaré dans [angular.json] (option ["proxyConfig": "proxy.conf.json"] de la cible [serve]) :

    // =========================================================================
// src/app/ex22-http/ex22.page.ts - une première requête HTTP vers le serveur
// -------------------------------------------------------------------------
// Le serveur JSON RdvMedecins doit être lancé (port 8080). On lui demande
// un captcha : GET /api/captcha -> { "id": "...", "svg": "<svg ...>" }.
//
//   - HttpClient : le client HTTP d'Angular (fourni à toute l'application
//     par provideHttpClient(), dans main.ts). http.get<T>(adresse) renvoie
//     un Observable : la requête part quand on s'y ABONNE (subscribe), et
//     la réponse arrive plus tard, son corps JSON déjà décodé ;
//   - une réponse d'erreur (4xx, 5xx) ou l'absence de réponse arrivent
//     dans la fonction error de l'abonnement ;
//   - l'adresse du serveur dépend de l'endroit où tourne l'application
//     (navigateur, émulateur Android, téléphone) : cf. commun/config.ts ;
//   - trois états à afficher : en cours, réussi, en erreur ;
//   - l'image du captcha est du SVG : une balise <img> sait l'afficher.
// =========================================================================

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { Component, DestroyRef, inject, signal } from '@angular/core';
import {
  IonBackButton, IonButton, IonButtons, IonCard, IonCardContent, IonContent, IonHeader, IonNote, IonProgressBar,
  IonTitle, IonToolbar,
} from '@ionic/angular';
import { Subscription } from 'rxjs';
import { config } from '../commun/config';
import { Captcha, imageCaptcha } from '../commun/types';

@Component({
  selector: 'app-ex22',
  imports: [
    IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle, IonContent, IonProgressBar, IonCard, IonCardContent,
    IonButton, IonNote,
  ],
  templateUrl: './ex22.page.html',
  styles: `
    .erreur { --background: #ffebee; --color: #333; margin: 12px 0; }
    .image { border: 1px solid #ddd; border-radius: 6px; padding: 4px; text-align: center; }
    .image img { height: 60px; }
    .id { font-family: monospace; font-size: 11px; margin: 8px 0; }
  `,
})
export class Ex22Page {
  private readonly http = inject(HttpClient);
  readonly serveur = config.urlServeur || '(même origine : /api, proxy de ng serve)';
  readonly imageCaptcha = imageCaptcha;

  // l'état de l'écran : des signaux
  readonly captcha = signal<Captcha | null>(null);
  readonly enCours = signal(true);
  readonly erreur = signal<string | null>(null);
  readonly nbRequetes = signal(0);

  // l'abonnement à la requête en cours (s'il y en a une)
  private requete?: Subscription;

  constructor() {
    this.charger(); // la première requête, dès la création de la page
    // la page détruite (bouton Retour) : la requête en cours est abandonnée
    inject(DestroyRef).onDestroy(() => this.requete?.unsubscribe());
  }

  charger(): void {
    // se désabonner d'une requête encore en cours l'ANNULE : sa réponse,
    // devenue inutile, ne sera jamais traitée (pas de réponse "périmée")
    this.requete?.unsubscribe();
    this.enCours.set(true);
    this.erreur.set(null);
    // <Captcha> : le type du corps JSON attendu (une promesse faite au
    // compilateur : rien n'est vérifié à l'exécution)
    this.requete = this.http.get<Captcha>(`${config.urlServeur}/api/captcha`).subscribe({
      // next : la réponse est arrivée (code 2xx), son corps JSON est décodé
      next: (captcha) => {
        this.captcha.set(captcha);
        this.nbRequetes.update((n) => n + 1);
        this.enCours.set(false);
      },
      // error : une réponse d'erreur (4xx, 5xx), ou pas de réponse du tout
      // (serveur arrêté, mauvaise adresse : status vaut alors 0)
      error: (e: HttpErrorResponse) => {
        this.erreur.set(e.status === 0 ? 'pas de réponse (status 0)' : `le serveur a répondu ${e.status}`);
        this.captcha.set(null);
        this.enCours.set(false);
      },
    });
  }
}

    • ligne 32 : une adresse [data:] contient le fichier lui-même : son type ([image/svg+xml]), puis son contenu, encodé par [encodeURIComponent] pour pouvoir figurer dans une adresse. Pourquoi pas insérer directement le texte SVG dans la page, par [[innerHTML]] ? [Angular] le refuserait : un SVG peut contenir des scripts, et [Angular] « nettoie » tout HTML inséré ainsi, en retirant les balises qu'il ne connaît pas comme sûres, dont [<svg>]. On pourrait le forcer ([DomSanitizer.bypassSecurityTrustHtml]), mais l'image est plus simple, et sans risque : une image affichée par [<img>] n'exécute jamais de script. En [Flutter], c'était le paquet [flutter_svg] qui dessinait le SVG ;

    Dans le navigateur, avec le proxy de [ng serve] ; puis le serveur ne répondant pas (pour cette copie d'écran, le script de capture fait échouer la requête, comme le ferait un serveur arrêté) :

    Les outils de développement de [Chrome] (F12), onglet « Réseau » (« Network »), montrent chaque requête HTTP de l'application, ses en-têtes et son corps : ici, [GET http://localhost:8100/api/captcha], transmise par le proxy. Sur le téléphone, on inspecte l'application depuis l'ordinateur, à l'adresse [chrome://inspect] (cf. chapitre « Déploiement ») ; les requêtes passant par [CapacitorHttp], c'est-à-dire par le code natif, y sont moins visibles.

    Le client HTTP d'[Angular] offre aussi, depuis la version 19, [httpResource()] : le pendant, pour une requête GET, de la [resource()] de l'exemple 19. On lui donne l'adresse, et il rend un objet à signaux ([isLoading()], [value()], [error()], [reload()]) : toute la gestion des trois états de cet exemple tiendrait en une ligne. On a préféré, pour une première requête, écrire ces états soi-même ; l'étude de cas utilisera [resource()].

    9.2. Exemple 23 : connexion, cookie et session

    9.2.1. Et le cookie ?

    Le serveur dépose le jeton JWT dans un cookie. Le client [Flutter] devait, à cet endroit, écrire un client HTTP qui lit l'en-tête [Set-Cookie] de chaque réponse, range les cookies (et les mémorise sur l'appareil), et les renvoie dans l'en-tête [Cookie] de chaque requête : une application [Flutter] n'a pas de navigateur pour le faire à sa place.

    Une application [Ionic], elle, n'a rien à écrire :

    • dans le navigateur de l'ordinateur, c'est le navigateur qui range le cookie et le renvoie, comme pour n'importe quel site. Le proxy de [ng serve] donne la même origine à l'application et à l'API : le cookie [SameSite=Strict] est accepté et renvoyé. Le code de l'application ne peut d'ailleurs ni lire ni écrire ce cookie ([HttpOnly]) ;
    • sur [Android], le greffon [CapacitorHttp] (exemple 22) fait passer les requêtes par le code natif. [Capacitor] installe, au démarrage de l'application, le gestionnaire de cookies d'[Android] (celui de la WebView) comme gestionnaire des requêtes natives : les cookies reçus y sont rangés, et renvoyés aux requêtes suivantes vers le même serveur. Ils sont conservés sur l'appareil (le nôtre a une durée de vie, [Max-Age=7200] ; seuls les cookies « de session », sans durée, sont effacés au démarrage de l'application) : on reste connecté quand on arrête puis relance l'application.

    Le jeton n'est donc jamais manipulé par le code de l'application, ni rangé par elle en clair sur l'appareil (le client [Flutter] le rangeait dans les [shared_preferences]).

// src/app/ex23-connexion/commande.ts - une ACTION, son état, son résultat
// -------------------------------------------------------------------------
// Une action asynchrone (se connecter, enregistrer...) a un état que
// l'écran doit montrer : est-elle EN COURS (bouton désactivé) ? s'est-elle
// terminée par une ERREUR (message) ? C'est le modèle "Command" des guides
// d'architecture (celui de Flutter, par exemple), réduit à l'essentiel :
//
//     readonly connexion = new Commande();
//     this.connexion.executer(() => this.seConnecter());   // lance l'action
//     connexion.enCours(), connexion.erreur()               // son état
//
// Son état est fait de SIGNAUX : le gabarit qui les lit est mis à jour
// quand la commande démarre et quand elle se termine.
// =========================================================================

import { signal } from '@angular/core';

export class Commande {
  private readonly _enCours = signal(false);
  private readonly _erreur = signal<unknown>(null);
  readonly enCours = this._enCours.asReadonly();
  readonly erreur = this._erreur.asReadonly();

  // exécute l'action, si une autre n'est pas déjà en cours
  async executer(action: () => Promise<void>): Promise<void> {
    if (this._enCours()) return; // pas de double envoi (double appui sur le bouton)
    this._enCours.set(true);
    this._erreur.set(null);
    try {
      await action();
    } catch (e) {
      this._erreur.set(e); // l'erreur est GARDÉE, pour être affichée
    } finally {
      // finally : exécuté dans TOUS les cas, succès ou erreur
      this._enCours.set(false);
    }
  }

  effacerErreur(): void {
    this._erreur.set(null);
  }
}

    Une action asynchrone (se connecter, enregistrer...) a un état que l'écran doit montrer : est-elle en cours (bouton désactivé) ? s'est-elle terminée par une erreur (message) ? C'est le modèle « Command » des guides d'architecture (celui de [Flutter] l'appelle ainsi), réduit à l'essentiel. Le cours [React] utilisait pour cela les « actions » de [React] 19 ([useActionState]).

    • lignes 19-23 : une simple classe (chaque écran crée la sienne avec [new]), dont l'état est fait de deux signaux privés, exposés en lecture seule. Le gabarit qui lit [enCours()] ou [erreur()] est mis à jour quand la commande démarre et quand elle se termine : c'est le rôle que jouait [ChangeNotifier] et [ListenableBuilder] en [Flutter] ;
    • lignes 26-38 : exécuter une action : si une autre est en cours, on ne fait rien (ligne 27 : pas de double envoi, si l'on appuie deux fois sur le bouton) ; sinon, la commande passe « en cours » ; en cas d'exception, l'erreur est gardée, pour être affichée (ligne 33) ; dans tous les cas ([finally], lignes 34-37), la commande n'est plus en cours. L'erreur est de type [unknown] : en [JavaScript], on peut lancer n'importe quelle valeur, et [TypeScript] ne sait donc rien de ce qu'attrape un [catch].

  readonly imageCaptcha = imageCaptcha;

  readonly utilisateur = signal<Utilisateur | null>(null); // null : personne n'est connecté

  readonly captcha = signal<Captcha | null>(null);
  readonly pret = signal(false); // la vérification de départ est-elle terminée ?
  readonly erreurServeur = signal<string | null>(null);
  readonly connexion = new Commande();
  // les champs du formulaire, reliés par [(ngModel)]
  readonly login = signal('admin');
  readonly password = signal('');
  readonly reponseCaptcha = signal('');

  constructor() {
    this.verifierSession();
  }

  private url(chemin: string): string {
    return `${config.urlServeur}/api${chemin}`;
  }

  // une requête GET dont on veut le corps JSON. Une réponse qui n'est pas un
  // 2xx (ou l'absence de réponse) rejette la Promise avec une HttpErrorResponse
  private lire<T>(chemin: string): Promise<T> {
    return firstValueFrom(this.http.get<T>(this.url(chemin)));
  }

  // un POST : l'objet corps est envoyé en JSON (entête content-type: application/json)
  private poster<T>(chemin: string, corps: object): Promise<T> {
    return firstValueFrom(this.http.post<T>(this.url(chemin), corps));
  }

  async chargerCaptcha(): Promise<void> {
    this.captcha.set(await this.lire<Captcha>('/captcha'));
    this.reponseCaptcha.set('');
  }

  private async chargerMedecins(): Promise<void> {
    this.medecins.set(await this.lire<Medecin[]>('/medecins'));
  }

  // 1. qui est connecté ? 200 -> l'utilisateur ; 401 -> personne
  private async verifierSession(): Promise<void> {
    try {
      this.utilisateur.set(await this.lire<Utilisateur>('/auth/moi'));
      await this.chargerMedecins();
    } catch (e) {
      // instanceof : un test de TYPE ; e.status : le code de statut (0 : pas de réponse)
      if (e instanceof HttpErrorResponse && e.status === 401) {
        await this.chargerCaptcha();
      } else if (e instanceof HttpErrorResponse && e.status !== 0) {
        this.erreurServeur.set(`Le serveur a répondu ${e.status}.`);
      } else {
        this.erreurServeur.set(`Le serveur JSON RdvMedecins est-il lancé (${config.urlServeur || 'port 8080'}) ?`);
      }
    }
    this.pret.set(true);
  }

  // le bouton "Se connecter" : la Commande exécute l'action et mémorise son erreur
  connecter(): void {
    this.connexion.executer(() => this.seConnecter());
  }

  // 2. la connexion
  private async seConnecter(): Promise<void> {
    try {
      const utilisateur = await this.poster<Utilisateur>('/auth/login', {
        login: this.login().trim(),
        password: this.password(),
        captchaId: this.captcha()?.id,
        captcha: this.reponseCaptcha(),
      });
      this.password.set('');
      this.utilisateur.set(utilisateur);
      await this.chargerMedecins();
    } catch (e) {
      if (!(e instanceof HttpErrorResponse)) throw e;
      // e.error : le corps JSON de la réponse d'erreur, { statusCode, cle, ... }
      const cle: string = e.error?.cle ?? 'ERRORS.SERVER_UNREACHABLE';
      await this.chargerCaptcha(); // chaque image ne sert qu'une fois
      // l'erreur que gardera la Commande
      throw new Error(`${e.status} - ${messages[cle] ?? cle}`);
    }
  }

  // le message de l'erreur gardée par la commande
  messageErreur(): string {
    const erreur = this.connexion.erreur();
    return erreur instanceof Error ? erreur.message : String(erreur);
  }

  // 4. la déconnexion
  async seDeconnecter(): Promise<void> {
    await this.poster('/auth/logout', {});
    this.utilisateur.set(null);
    this.medecins.set([]);
    await this.chargerCaptcha();
  }
}

// src/app/commun/erreur-api.ts - UNE classe pour toutes les erreurs de l'API
// -------------------------------------------------------------------------
// Toutes les réponses d'erreur du serveur RdvMedecins ont la même forme :
//   { "statusCode": 409, "cle": "ERRORS.LOGIN_TAKEN", "params": {...}, "champs": {...} }
// Mais une requête peut aussi échouer AUTREMENT : pas de réponse du tout
// (réseau coupé, serveur arrêté, mauvaise adresse), ou une réponse qui ne
// vient pas de notre serveur (une page d'erreur d'un proxy). Le client
// HTTP d'Angular signale tous ces échecs par une HttpErrorResponse ; on la
// convertit en UNE classe, ErreurApi, qui porte la clé de traduction
// envoyée par le serveur (et, s'il y en a, ses paramètres et l'erreur de
// chaque champ).

import { HttpErrorResponse } from '@angular/common/http';

// un objet { nom: texte }
export type Textes = Record<string, string>;

// "extends Error" : une erreur JavaScript à part entière, qu'on lance
// (throw) et qu'on attrape (catch) ; message vaut "409 ERRORS.LOGIN_TAKEN"
export class ErreurApi extends Error {
  constructor(
    readonly statusCode: number, // 0 : le serveur n'a pas répondu
    readonly cle: string, // ex : 'ERRORS.LOGIN_TAKEN'
    readonly params: Textes = {},
    readonly champs: Textes = {},
  ) {
    super(`${statusCode} ${cle}`);
    this.name = 'ErreurApi';
  }

  // une réponse en erreur du client HTTP d'Angular -> une ErreurApi
  static depuisReponse(reponse: HttpErrorResponse): ErreurApi {
    // status 0 : aucune réponse (réseau coupé, serveur arrêté, mauvaise adresse)
    if (reponse.status === 0) {
      return new ErreurApi(0, 'ERRORS.SERVER_UNREACHABLE');
    }
    // error : le corps de la réponse, déjà décodé s'il s'agit de JSON
    const corps: unknown = reponse.error;
    if (estUnObjet(corps) && typeof corps['cle'] === 'string') {
      return new ErreurApi(reponse.status, corps['cle'], textes(corps['params']), textes(corps['champs']));
    }
    // pas de clé : le proxy ou le réseau ont répondu à sa place
    return new ErreurApi(
      reponse.status,
      reponse.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR',
    );
  }
}

// un "garde de type" : si la fonction rend true, TypeScript sait que
// valeur est un objet dont on peut lire les propriétés
function estUnObjet(valeur: unknown): valeur is Record<string, unknown> {
  return typeof valeur === 'object' && valeur !== null && !Array.isArray(valeur);
}

// un objet JSON { "nom": "ERRORS..." } -> Textes (vide sinon)
function textes(json: unknown): Textes {
  if (!estUnObjet(json)) return {};
  return Object.fromEntries(Object.entries(json).map(([cle, valeur]) => [cle, String(valeur)]));
}

// -------------------------------------------------------------------------
// Dans l'exemple 23, chaque requête répétait les mêmes gestes : adresse du
// serveur, préfixe /api, transformation de l'Observable en Promise, lecture
// du corps d'erreur... On les regroupe ici, dans un SERVICE :

//   const medecins = await this.api.get<Personne[]>('/medecins');
//   await this.api.post('/rendez-vous', { jour, idCreneau: 3 });

//   - en cas de succès, la Promise rend le corps JSON, DÉCODÉ ;

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { inject, Injectable } from '@angular/core';
import { firstValueFrom } from 'rxjs';
import { config } from './config';
import { ErreurApi } from './erreur-api';

export type Methode = 'GET' | 'POST' | 'PUT' | 'DELETE';

// providedIn: 'root' : un seul exemplaire, pour toute l'application
@Injectable({ providedIn: 'root' })
export class Api {
  private readonly http = inject(HttpClient);

  // <T> : le type de la réponse attendue, choisi par l'appelant
  async requete<T>(methode: Methode, url: string, corps?: unknown): Promise<T> {
    try {
      // http.request renvoie un Observable ; firstValueFrom le transforme en
      // Promise (la requête part à ce moment-là). Un objet corps est envoyé
      // en JSON (entête content-type: application/json, que le serveur exige
      // pour un POST) ; la réponse JSON est décodée (null si son corps est vide)
      return await firstValueFrom(this.http.request<T>(methode, `${config.urlServeur}/api${url}`, { body: corps }));
    } catch (e) {
      // le client HTTP signale TOUT échec (4xx, 5xx, pas de réponse) par une
      // HttpErrorResponse : on la convertit. Le reste (une anomalie) passe tel quel
      throw e instanceof HttpErrorResponse ? ErreurApi.depuisReponse(e) : e;
    }
  }

  get<T>(url: string): Promise<T> {
    return this.requete<T>('GET', url);
  }

  // un POST a toujours un corps JSON : {} par défaut
  post<T>(url: string, corps: unknown = {}): Promise<T> {
    return this.requete<T>('POST', url, corps);
  }

  put<T>(url: string, corps: unknown): Promise<T> {
    return this.requete<T>('PUT', url, corps);
  }

  delete<T>(url: string, corps?: unknown): Promise<T> {
    return this.requete<T>('DELETE', url, corps);
  }
}

import { computed, inject, Injectable, signal } from '@angular/core';
import { ErreurApi } from '../commun/erreur-api';
import { Agenda, CreneauAgenda, horaire, Personne, Utilisateur } from '../commun/types';
import { RdvMedecins } from './rdvmedecins';

// une date -> "2026-10-07" (le jour LOCAL ; toISOString donnerait le jour à Greenwich)
export function formatJour(d: Date): string {
  const deuxChiffres = (n: number) => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${deuxChiffres(d.getMonth() + 1)}-${deuxChiffres(d.getDate())}`;
}

// demain : le jour d'aujourd'hui, plus un
function demain(): Date {
  const d = new Date();
  d.setDate(d.getDate() + 1);
  return d;
}

export interface Message {
  succes: boolean;
  texte: string;
}

@Injectable()
export class AgendaModele {
  private readonly rdvmedecins = inject(RdvMedecins);

  // ---- l'état ----
  readonly utilisateur = signal<Utilisateur | null>(null);
  readonly medecins = signal<Personne[]>([]);
  readonly clients = signal<Personne[]>([]);
  readonly idMedecin = signal<number | null>(null);
  readonly jour = signal(formatJour(demain()));
  readonly idClient = signal<number | null>(null);
  readonly agenda = signal<Agenda | null>(null);
  readonly chargement = signal(false);
  readonly message = signal<Message | null>(null);

  private readonly cache = new Map<string, Agenda>();
  private numeroLecture = 0;

  // ---- des valeurs calculées ----
  readonly connecte = computed(() => this.utilisateur() !== null);
  readonly gestionnaire = computed(() => this.connecte() && this.utilisateur()?.role !== 'USER');

  // ---- les actions ----
  async changerUtilisateur(u: Utilisateur | null): Promise<void> {
    this.utilisateur.set(u);
    this.medecins.set([]);
    this.clients.set([]);
    this.agenda.set(null);
    this.idMedecin.set(null);
    this.message.set(null);
    this.cache.clear(); // les droits ont changé : on oublie tout
    if (u === null) return;
    this.medecins.set(await this.rdvmedecins.getMedecins());
    // un USER recevrait 403
    if (this.gestionnaire()) this.clients.set(await this.rdvmedecins.getClients());
  }

  choisirMedecin(id: number): void {
    this.idMedecin.set(id);
    this.message.set(null);
    this.lireAgenda();
  }

  choisirJour(jour: string): void {
    this.jour.set(jour);
    this.message.set(null);
    this.lireAgenda();
  }

  choisirClient(id: number | null): void {
    this.idClient.set(id);
  }

  reserver(c: CreneauAgenda): Promise<void> {
    return this.agir(
      () => this.rdvmedecins.reserver(this.jour(), c.id, this.gestionnaire() ? this.idClient() : null),
      `Créneau ${horaire(c)} réservé.`,
    );
  }

  annuler(c: CreneauAgenda): Promise<void> {
    return this.agir(() => this.rdvmedecins.annuler(c.idRv!), `Rendez-vous de ${horaire(c)} annulé.`);
  }

  // une action, puis TOUJOURS une relecture de l'agenda : c'est le SERVEUR qui fait foi
  private async agir(action: () => Promise<void>, succes: string): Promise<void> {
    try {
      await action();
      this.message.set({ succes: true, texte: succes });
    } catch (e) {
      this.message.set({ succes: false, texte: e instanceof ErreurApi ? e.message : String(e) });
    }
    await this.lireAgenda();
  }

  private async lireAgenda(): Promise<void> {
    const id = this.idMedecin();
    if (id === null) return;
    const cle = `${id}/${this.jour()}`;
    const numero = ++this.numeroLecture;
    // le cache d'abord (ou rien), puis la lecture
    this.agenda.set(this.cache.get(cle) ?? null);
    this.chargement.set(true);
    try {
      const lu = await this.rdvmedecins.getAgenda(id, this.jour());
      if (numero !== this.numeroLecture) return; // une lecture plus récente a été lancée
      this.cache.set(cle, lu);
      this.agenda.set(lu);
    } catch (e) {
      if (numero !== this.numeroLecture) return;
      this.agenda.set(null);
      this.message.set({ succes: false, texte: e instanceof ErreurApi ? e.message : String(e) });
    }
    this.chargement.set(false);
  }
}

// src/app/ex25-erreurs-serveur/ex25.page.ts - afficher les erreurs du SERVEUR

// La gestion des clients (compte admin). Ce formulaire ne fait
// VOLONTAIREMENT aucune validation sur le téléphone : tout est envoyé au
// serveur, qui répond, en cas de refus, par une erreur JSON (convertie en
// ErreurApi par commun/api.ts) :
//
//   400 { cle: 'ERRORS.INVALID_FORM', champs: { nom: 'ERRORS.LASTNAME_REQUIRED' } }
//   409 { cle: 'ERRORS.PATIENT_ALREADY_EXISTS', champs: { prenom: ..., nom: ... } }
//   409 { cle: 'ERRORS.CONCURRENT_UPDATE' }         (verrou optimiste)
//
// L'erreur de CHAQUE champ (ErreurApi.champs) est donnée à son contrôle de
// formulaire (setErrors) : ion-input l'affiche sous le champ (errorText).
// Son message est la CLÉ envoyée par le serveur, que l'écran traduit
// (dictionnaires de l'exemple 21). Modifier un champ efface son erreur.
// Essayez : un nom vide, un titre "Dr", un homonyme (Alice DURAND), un
// login déjà pris (martin), la même fiche modifiée sur deux appareils...
// =========================================================================

import { Component, inject, signal } from '@angular/core';
import { NonNullableFormBuilder, ReactiveFormsModule } from '@angular/forms';
import {
  IonBackButton, IonButton, IonButtons, IonCard, IonCardContent, IonCardHeader, IonCardTitle, IonContent, IonHeader,
  IonIcon, IonInput, IonItem, IonLabel, IonList, IonNote, IonPopover, IonSelect, IonSelectOption, IonText, IonTitle,
  IonToolbar,
} from '@ionic/angular';
import { addIcons } from 'ionicons';
import { createOutline, languageOutline, trashOutline } from 'ionicons/icons';
import { Api } from '../commun/api';
import { BarreConnexion } from '../commun/barre-connexion';
import { ErreurApi, Textes } from '../commun/erreur-api';
import { nomComplet, Personne, Utilisateur } from '../commun/types';
import { injecterConfirmation } from '../ex16-confirmation/confirmation';
import { langues, Traductions } from '../ex21-i18n/traductions';
import { Commande } from '../ex23-connexion/commande';

// les champs du formulaire, et un message à traduire (une clé et ses paramètres)
type Champ = 'titre' | 'prenom' | 'nom' | 'login' | 'password';
interface Succes {
  cle: string;
  params: Textes;
}

@Component({
  selector: 'app-ex25',
  imports: [
    ReactiveFormsModule, IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle, IonButton, IonIcon, IonPopover,
    IonContent, IonList, IonItem, IonLabel, IonCard, IonCardHeader, IonCardTitle, IonCardContent, IonSelect,
    IonSelectOption, IonInput, IonText, IonNote, BarreConnexion,
  ],
  templateUrl: './ex25.page.html',
  // les traductions de la page, avec les dictionnaires ex25-fr.json et ex25-en.json
  providers: [{ provide: Traductions, useFactory: () => new Traductions('ex25') }],
  styles: `
    .avertissement { --background: #fff8e1; --color: #333; }
    .message { margin-top: 12px; }
    .statut { font-size: 12px; }
  `,
})
export class Ex25Page {
  private readonly api = inject(Api);
  private readonly confirmer = injecterConfirmation();
  readonly tr = inject(Traductions);
  readonly langues = langues;
  readonly titres = ['Mr', 'Mme', 'Melle', 'Dr']; // "Dr" : le serveur le refusera
  readonly nomComplet = nomComplet;

  readonly utilisateur = signal<Utilisateur | null>(null);
  readonly clients = signal<Personne[]>([]);

  // le formulaire : AUCUNE règle de validation, tout est vérifié par le serveur
  readonly formulaire = inject(NonNullableFormBuilder).group({
    titre: ['Mr'],
    prenom: [''],
    nom: [''],
    login: [''],
    password: [''],
  });
  // null : création ; sinon, l'id du client modifié, et la version lue avec sa fiche
  readonly idEdite = signal<number | null>(null);
  private version = 0;

  // le message général de la dernière erreur, et celui d'un succès
  readonly erreurPage = signal<ErreurApi | null>(null);
  readonly succes = signal<Succes | null>(null);
  // l'envoi au serveur : une Commande (exemple 23), qui dit s'il est en cours
  readonly envoi = new Commande();

  constructor() {
    addIcons({ languageOutline, createOutline, trashOutline });
    this.tr.demarrer();
  }

  estAdmin(): boolean {
    return this.utilisateur()?.role === 'ADMIN';
  }

  private async recharger(): Promise<void> {
    this.clients.set(await this.api.get<Personne[]>('/clients'));
  }

  async surConnexion(u: Utilisateur | null): Promise<void> {
    this.utilisateur.set(u);
    this.clients.set([]);
    if (u?.role === 'ADMIN') await this.recharger();
  }

  // l'erreur d'un champ, renvoyée par le serveur, traduite ('' : pas d'erreur)
  erreurChamp(champ: Champ): string {
    const cle = this.formulaire.controls[champ].errors?.['serveur'];
    return typeof cle === 'string' ? this.tr.t(cle) : '';
  }

  private effacerMessages(): void {
    this.erreurPage.set(null);
    this.succes.set(null);
  }

  nouveau(): void {
    this.idEdite.set(null);
    this.version = 0;
    // reset : les valeurs de départ, et plus aucune erreur
    this.formulaire.reset();
    this.effacerMessages();
  }

  editer(c: Personne): void {
    this.idEdite.set(c.id);
    // la VERSION lue avec la fiche repart avec la modification : si quelqu'un
    // a modifié la fiche entre-temps, le serveur répondra 409 CONCURRENT_UPDATE
    this.version = c.version;
    this.formulaire.reset({ titre: c.titre, prenom: c.prenom, nom: c.nom, login: c.login ?? '', password: '' });
    this.effacerMessages();
  }

  // le bouton "Enregistrer"
  envoyer(): void {
    this.envoi.executer(() => this.enregistrer());
  }

  private async enregistrer(): Promise<void> {
    this.effacerMessages();
    const saisie = { ...this.formulaire.getRawValue(), version: this.version };
    const id = this.idEdite();
    try {
      const client =
        id === null
          ? await this.api.post<Personne>('/clients', saisie)
          : await this.api.put<Personne>(`/clients/${id}`, saisie);
      this.nouveau(); // formulaire vidé, messages effacés...
      // ... sauf celui-ci
      this.succes.set({
        cle: id === null ? 'FORM.AJOUTE' : 'FORM.MODIFIE',
        params: { nom: `${client.prenom} ${client.nom}`, login: client.login ?? '' },
      });
      await this.recharger();
    } catch (e) {
      if (!(e instanceof ErreurApi)) throw e;
      this.erreurPage.set(e); // le message général
      // l'erreur de chaque champ : elle est donnée à son contrôle, qui
      // devient invalide (ng-invalid) ; markAsTouched le marque "touché"
      // (ng-touched) : Ionic affiche alors son errorText
      for (const [champ, cle] of Object.entries(e.champs)) {
        const controle = this.formulaire.get(champ);
        controle?.setErrors({ serveur: cle });
        controle?.markAsTouched();
      }
    }
  }

  async supprimer(c: Personne): Promise<void> {
    const nom = `${c.prenom} ${c.nom}`;
    if (!(await this.confirmer(this.tr.t('FORM.CONFIRMER_SUPPRESSION', { nom })))) return;
    this.effacerMessages();
    try {
      await this.api.delete(`/clients/${c.id}`);
      this.succes.set({ cle: 'FORM.SUPPRIME', params: { nom } });
    } catch (e) {
      if (e instanceof ErreurApi) this.erreurPage.set(e);
    }
    await this.recharger();
  }
}
