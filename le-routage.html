    5. Le routage

    Une application a plusieurs écrans. Sur le web, chaque écran a une adresse (/ex17/medecins/2) : on peut le désigner, l'ouvrir depuis un lien, le recharger, le protéger par des gardes. [Angular] gère ces adresses avec son routeur (le paquet [@angular/router]), que nous utilisons depuis le premier exemple : la page d'accueil de l'application des exemples associe l'adresse /ex01 à la page de l'exemple 01, /ex02 à celle de l'exemple 02, etc. [Ionic] ne remplace pas ce routeur : il s'appuie sur lui, et y ajoute ce qu'attend une application mobile. Son composant [<ion-router-outlet>] fait des pages une pile : une nouvelle page est empilée au-dessus de la précédente (avec l'animation d'Android), le bouton Retour du téléphone la dépile, et la page précédente, restée en mémoire, réapparaît telle qu'on l'avait laissée. C'est le [Navigator] de [Flutter] et le paquet [go_router] réunis.

    5.1. Exemple 17 : le routeur

    L'exemple 17 a six pages : un accueil, la liste des médecins, le détail d'un médecin, une recherche, une page « À propos » chargée à la demande, et une page pour les adresses inconnues. Les cinq premières sont réunies dans une « coquille », avec une barre d'onglets en bas de l'écran (quatre onglets : le détail d'un médecin appartient à l'onglet Médecins).

    // =========================================================================
// src/app/ex17-routeur/routes.ts - les ROUTES de l'exemple 17
// -------------------------------------------------------------------------
// Une application a plusieurs écrans (des "pages"). Le ROUTEUR d'Angular
// associe une ADRESSE (un chemin, comme sur le web : /ex17/medecins/2) à
// une page. Ionic s'appuie sur lui : son <ion-router-outlet> en fait une
// PILE de pages (on empile, on dépile, le bouton Retour d'Android dépile).
// Ces routes sont les ENFANTS de la route /ex17 de app.routes.ts
// (loadChildren) : leurs chemins sont relatifs à /ex17.
//   'medecins/:id'   :id est un paramètre (/ex17/medecins/2 -> id = "2") ;
//   children         des routes affichées DANS la "coquille" (la barre du
//                    haut, la barre d'onglets du bas) ;
//   redirectTo       une redirection : l'ancienne adresse mène à la nouvelle ;
//   '**'             le "joker" : toute adresse qu'aucune route ne reconnaît ;
//   title            le titre du document (onglet du navigateur) ;
//   loadComponent    chargement DIFFÉRÉ : le code de la page n'est
//                    téléchargé qu'à sa première visite.
// =========================================================================

import { ResolveFn, Routes } from '@angular/router';
import { Coquille } from './coquille';
import { medecins } from './donnees';
import { Accueil } from './pages/accueil.page';
import { DetailMedecin } from './pages/detail-medecin.page';
import { ListeMedecins } from './pages/liste-medecins.page';
import { PageIntrouvable } from './pages/page-introuvable.page';
import { Recherche } from './pages/recherche.page';

// le titre de la page d'un médecin, calculé d'après le paramètre :id de l'adresse
const titreMedecin: ResolveFn<string> = (route) => {
  const medecin = medecins.find((m) => m.id === Number(route.paramMap.get('id')));
  return medecin ? `${medecin.prenom} ${medecin.nom}` : 'Médecin inconnu';
};

export const routes: Routes = [
  {
    // la coquille (Coquille) contient la barre d'onglets ; ses routes
    // enfants sont affichées DANS la coquille, au-dessus de la barre
    path: '',
    component: Coquille,
    children: [
      // /ex17 tout court : on va à l'onglet d'accueil
      { path: '', redirectTo: 'accueil', pathMatch: 'full' },
      { path: 'accueil', title: 'Accueil', component: Accueil },
      { path: 'medecins', title: 'Médecins', component: ListeMedecins },
      // une page à PARAMÈTRE : /ex17/medecins/2 ; elle commence par
      // 'medecins' : elle appartient à l'onglet Médecins, dont elle
      // empile une page au-dessus de la liste
      { path: 'medecins/:id', title: titreMedecin, component: DetailMedecin },
      // /ex17/recherche?q=pédiatre : le paramètre q est un paramètre de REQUÊTE
      { path: 'recherche', title: 'Recherche', component: Recherche },
      // chargement différé : import() est une importation DYNAMIQUE
      // (une Promise) ; le code de la page est placé dans un fichier à part
      {
        path: 'a-propos',
        title: 'À propos',
        loadComponent: () => import('./pages/a-propos.page').then((m) => m.APropos),
      },
      // une redirection : la route n'a pas de page, elle renvoie à une autre adresse
      { path: 'docteurs', redirectTo: 'medecins' },
    ],
  },
  // toute autre adresse sous /ex17 : la page introuvable, HORS de la coquille
  { path: '**', title: 'Page introuvable', component: PageIntrouvable },
];

    Une route associe un chemin à une page. Les routes de l'exemple 17 sont rangées dans son dossier, et la route /ex17 de l'application les charge par [loadChildren] (plus loin) : ce sont des routes enfants de /ex17, et leurs chemins sont relatifs à /ex17 ([accueil] désigne l'adresse /ex17/accueil).

    • lignes 30-33 : une fonction de type [ResolveFn<string>], qui calcule le titre de la page d'un médecin d'après le paramètre [:id] de l'adresse ([route.paramMap.get('id')]). La propriété [title] d'une route est le titre du document (l'onglet du navigateur sur le web) : une chaîne, ou une telle fonction. C'est le pendant du widget [Title] de [Flutter] ;
    • lignes 36-41 : la coquille de l'exemple. La route n'a pas de chemin propre ([path: '']) ; elle affiche le composant [Coquille] (la barre du haut et la barre d'onglets), et ses routes enfants ([children]) sont affichées DANS la coquille. C'est l'équivalent de la [ShellRoute] de [go_router] ;
    • ligne 43 : l'adresse /ex17 tout court est redirigée vers /ex17/accueil. [pathMatch: 'full'] : la route ne s'applique que si l'adresse restante est vide (sans cela, le chemin vide, qui est le début de toute adresse, s'appliquerait toujours) ;
    • lignes 44-45 : une route ordinaire : son chemin, son titre, et le composant de sa page ;
    • ligne 49 : une route à paramètre : [medecins/:id], où [:id] est un paramètre ([/ex17/medecins/2] : [id] vaut ["2"], toujours une chaîne). Avec [go_router], cette route était imbriquée dans celle de la liste ; ici, elle est sa voisine. Son chemin commence par [medecins] : pour [Ionic], elle appartient à l'onglet Médecins, et sa page est empilée au-dessus de la liste, dans la pile de cet onglet ;
    • ligne 51 : la recherche. Ses paramètres de requête (après le [?] : [/ex17/recherche?q=pédiatre]) ne figurent pas dans le chemin de la route : toute route peut en recevoir ;
    • lignes 54-58 : le chargement différé. [loadComponent] est une fonction qui rend une [Promise] : [import('./pages/a-propos.page')] est une importation dynamique de [JavaScript], qui charge le fichier quand on l'exécute, et [then] en extrait le composant. La compilation ([ng build]) place alors le code de la page dans un fichier [JavaScript] à part, téléchargé à la première visite de la page. C'est le pendant de l'importation [deferred as] de [Dart] ;
    • ligne 60 : une redirection : la route n'a pas de page, elle renvoie à une autre adresse. [redirectTo] peut aussi être une fonction, qui calcule l'adresse ;
    • ligne 64 : la route joker [**] reconnaît toute adresse qu'aucune route précédente n'a reconnue (le routeur essaie les routes dans l'ordre). Elle est placée hors de la coquille : la page introuvable a sa propre barre du haut. C'est le pendant de l'[errorBuilder] de [go_router].

    // =========================================================================
// src/app/ex17-routeur/coquille.ts - la "coquille" de l'exemple 17
// -------------------------------------------------------------------------
// La barre du haut, la barre d'onglets du bas, et, entre les deux, la page
// de la route courante. C'est le composant <ion-tabs> d'Ionic :
//   - <ion-tab-bar slot="bottom"> : la barre d'onglets, en bas ;
//   - <ion-tab-button tab="medecins"> : un onglet ; le toucher mène à
//     l'adresse /ex17/medecins. L'onglet actif est celui dont le nom est le
//     premier segment de l'adresse (après /ex17) : /ex17/medecins/2 -> Médecins ;
//   - chaque onglet a sa PROPRE pile de pages : on peut entrer dans le
//     détail d'un médecin, passer à l'onglet Recherche, revenir à l'onglet
//     Médecins... et retrouver le détail.
// =========================================================================

import { Component, computed, inject } from '@angular/core';
import { Router } from '@angular/router';
import {
  IonBackButton, IonButtons, IonHeader, IonIcon, IonLabel, IonTabBar, IonTabButton, IonTabs, IonTitle, IonToolbar,
} from '@ionic/angular';
import { addIcons } from 'ionicons';
import { home, informationCircle, people, search } from 'ionicons/icons';
import { ChargementDiffere } from './pages/chargement-differe';

// les onglets : le nom de l'onglet (= le chemin, après /ex17), le libellé, l'icône
const onglets = [
  { tab: 'accueil', libelle: 'Accueil', icone: 'home' },
  { tab: 'medecins', libelle: 'Médecins', icone: 'people' },
  { tab: 'recherche', libelle: 'Recherche', icone: 'search' },
  { tab: 'a-propos', libelle: 'À propos', icone: 'information-circle' },
];

@Component({
  selector: 'app-ex17-coquille',
  imports: [
    IonTabs, IonTabBar, IonTabButton, IonIcon, IonLabel, IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle,
    ChargementDiffere,
  ],
  templateUrl: './coquille.html',
  styles: `
    .adresse {
      background: var(--ion-color-light);
      color: var(--ion-color-light-contrast);
      padding: 8px;
      font-family: monospace;
      font-size: 12px;
    }
  `,
})
export class Coquille {
  readonly onglets = onglets;
  private readonly router = inject(Router);

  // l'adresse courante. lastSuccessfulNavigation est un SIGNAL du routeur :
  // la dernière navigation réussie ; finalUrl : son adresse, après les
  // redirections. decodeURIComponent : %C3%A9 redevient é
  readonly adresse = computed(() => {
    const navigation = this.router.lastSuccessfulNavigation();
    return navigation?.finalUrl ? decodeURIComponent(this.router.serializeUrl(navigation.finalUrl)) : '';
  });

  constructor() {
    // les icônes utilisées par le gabarit
    addIcons({ home, people, search, informationCircle });
  }
}

  <ion-header slot="top">

    La coquille est le composant [<ion-tabs>] d'[Ionic] : une barre d'onglets, et, au-dessus, la page de l'onglet choisi.

    • lignes 25-30 (coquille.ts) : les onglets : un nom (qui est aussi le chemin de la route, après /ex17), un libellé et une icône ;
    • lignes 56-59 (coquille.ts) : l'adresse courante, un signal calculé ([computed]). Le routeur expose des signaux : [lastSuccessfulNavigation()], la dernière navigation réussie, et [currentNavigation()], la navigation en cours (plus loin). [finalUrl] est l'adresse atteinte, après les redirections ; [serializeUrl] la met sous forme de chaîne ; [decodeURIComponent] décode les caractères encodés ([%C3%A9] redevient [é]). Le signal étant relu à chaque navigation, l'adresse affichée suit ;
    • ligne 63 (coquille.ts) : les icônes utilisées par le gabarit ;
    • lignes 7-18 (coquille.html) : la barre du haut. [<ion-tabs>] place les éléments marqués [slot="top"] au-dessus des pages des onglets, et les autres en dessous. Le bouton Retour de cette barre-là dépile la coquille tout entière : il ramène au menu des exemples ;
    • ligne 15 (coquille.html) : l'adresse courante ;
    • ligne 17 (coquille.html) : une barre de progression, affichée pendant les navigations (plus loin) ;
    • lignes 20-21 (coquille.html) : [<ion-tabs>] place lui-même, entre les deux barres, un [<ion-router-outlet>] : la page de la route enfant courante. On ne l'écrit pas ;
    • lignes 24-31 (coquille.html) : la barre d'onglets du bas ([<ion-tab-bar slot="bottom">]), typique d'une application mobile, le pendant de la [NavigationBar] de [Flutter]. Chaque [<ion-tab-button [tab]="...">] est un onglet ; le toucher mène à l'adresse /ex17/<nom de l'onglet>.

    Deux différences avec [go_router] :

    • l'onglet actif n'est pas calculé par le code : [<ion-tabs>] le déduit de l'adresse (l'onglet dont le nom est le premier segment de l'adresse, après /ex17 : [/ex17/medecins/2] désigne l'onglet [medecins]) ;
    • chaque onglet a sa propre pile de pages. On entre dans le détail d'un médecin, on passe à l'onglet Recherche, on revient à l'onglet Médecins : on retrouve le détail du médecin, et le bouton Retour ramène à la liste. C'est le comportement habituel des applications mobiles (celles d'[Android] et d'[iOS]).

@Component({
  selector: 'app-ex17-detail-medecin',

export class DetailMedecin {

  readonly medecin = computed(() => medecins.find((m) => m.id === Number(this.id())));

    if (this.outlet.canGoBack()) {

import { Injectable, signal } from '@angular/core';

export type Role = 'ADMIN' | 'DOCTOR' | 'USER';

export interface Utilisateur {
  login: string;
  role: Role;
}

// trois comptes "en dur" (mot de passe = login)
const comptes: Record<string, Role> = { admin: 'ADMIN', pelissier: 'DOCTOR', martin: 'USER' };

// providedIn: 'root' : UN seul exemplaire, pour toute l'application
@Injectable({ providedIn: 'root' })
export class Session {
  // l'état : null, personne n'est connecté
  private readonly _utilisateur = signal<Utilisateur | null>(null);
  // asReadonly : on peut lire le signal, pas le modifier
  readonly utilisateur = this._utilisateur.asReadonly();

  connecter(login: string, password: string): boolean {
    const role = comptes[login];
    if (role === undefined || password !== login) {
      return false;
    }
    this._utilisateur.set({ login, role });
    return true;
  }

  deconnecter(): void {
    this._utilisateur.set(null);
  }
}

// src/app/ex18-gardes/routes.ts - des routes PROTÉGÉES par des gardes
// -------------------------------------------------------------------------
// canActivate : la liste des GARDES d'une route, des fonctions (de type
// CanActivateFn) que le routeur appelle AVANT d'y aller. Un garde reçoit
// la route demandée et l'état de la navigation (state.url : l'adresse
// demandée), et renvoie :
//   - true : la navigation continue ;
//   - false : elle est annulée ;
//   - un UrlTree (une adresse fabriquée par le routeur) : la navigation
//     est remplacée par une navigation vers cette adresse.
// Un garde peut utiliser inject() : il est appelé dans un "contexte
// d'injection".
//
// C'est l'équivalent, côté client, des gardes NestJS (JwtAuthGuard,
// RolesGuard) - avec une différence FONDAMENTALE : un garde du client n'est
// qu'un confort. L'application est entre les mains de l'utilisateur, qui
// peut la modifier à volonté. La vraie protection des données reste celle
// du SERVEUR (cf. chapitre sur la boîte noire).
// =========================================================================

import { inject } from '@angular/core';
import { CanActivateFn, Router, Routes } from '@angular/router';
import { Coquille } from './coquille';
import { Accueil } from './pages/accueil.page';
import { Agenda } from './pages/agenda.page';
import { Connexion } from './pages/connexion.page';
import { Role, Session } from './session';

// le garde "connexion requise" : pas connecté -> à la page de connexion, en
// retenant où l'on voulait aller (paramètre returnUrl)
export const connexionRequise: CanActivateFn = (route, state) => {
  if (inject(Session).utilisateur() === null) {
    return inject(Router).createUrlTree(['/ex18/connexion'], { queryParams: { returnUrl: state.url } });
  }
  return true;
};

// le garde "rôle requis" : une fonction qui FABRIQUE un garde
export function roleRequis(...roles: Role[]): CanActivateFn {
  return (route, state) => {
    const u = inject(Session).utilisateur();
    if (u === null || !roles.includes(u.role)) {
      // connecté, mais pas avec le bon rôle : retour à l'accueil, avec un motif
      return inject(Router).createUrlTree(['/ex18'], { queryParams: { refus: state.url } });
    }
    return true;
  };
}

export const routes: Routes = [
  {
    path: '',
    component: Coquille,
    children: [
      { path: '', pathMatch: 'full', component: Accueil },
      { path: 'connexion', component: Connexion },
      { path: 'agenda', canActivate: [connexionRequise], component: Agenda },
      {
        path: 'administration',
        // les gardes, dans l'ordre : le premier qui ne renvoie pas true l'emporte
        canActivate: [connexionRequise, roleRequis('ADMIN')],
        // le code de la page n'est chargé qu'une fois les gardes franchis
        loadComponent: () => import('./pages/administration.page').then((m) => m.Administration),
      },
      // toute autre adresse (aucune route ne correspond) : retour à l'accueil
      { path: '**', redirectTo: '' },
    ],
  },
];

    Un garde d'activation est une fonction de type [CanActivateFn], placée dans la liste [canActivate] d'une route. Le routeur l'appelle avant d'aller à cette route ; elle reçoit la route demandée et l'état de la navigation ([state.url] : l'adresse demandée), et rend :

    • [true] : la navigation continue ;
    • [false] : la navigation est annulée ;
    • un [UrlTree], une adresse fabriquée par le routeur ([router.createUrlTree]) : la navigation est remplacée par une navigation vers cette adresse.

    Un garde peut aussi rendre une [Promise] ou un [Observable] de l'une de ces valeurs (pour interroger un serveur, par exemple). Le code :

    • lignes 32-37 : le garde « connexion requise » : pas connecté ? à la page de connexion, en retenant où l'on voulait aller (paramètre de requête [returnUrl]). Le garde utilise [inject()] : le routeur l'appelle dans un « contexte d'injection » ;
    • lignes 40-49 : le garde « rôle requis » est FABRIQUÉ par une fonction, qui reçoit les rôles permis ([...roles] : autant de paramètres qu'on veut, réunis dans un tableau) et rend le garde. Connecté, mais sans le bon rôle : retour à l'accueil, avec un motif (paramètre [refus]) ;
    • lignes 52-55 : la coquille et ses routes enfants, comme dans l'exemple 17 ;
    • ligne 58 : l'agenda exige d'être connecté ;
    • lignes 59-65 : l'administration exige d'être connecté ET d'avoir le rôle ADMIN. Les gardes de la liste sont appelés dans l'ordre ; le premier qui ne rend pas [true] l'emporte (c'était l'enchaînement par [??] avec [go_router]). Le code de la page n'est chargé ([loadComponent]) qu'une fois les gardes franchis ;
    • ligne 67 : toute autre adresse sous /ex18 ramène à l'accueil.

    C'est l'équivalent, côté client, des gardes du serveur [NestJS] ([JwtAuthGuard], [RolesGuard]), avec une différence FONDAMENTALE : un garde du client n'est qu'un confort (ne pas afficher un écran inutile). L'application est entre les mains de l'utilisateur, qui peut la modifier à volonté ; la vraie protection des données reste celle du serveur, qui revérifie tout à chaque requête (cf. le chapitre sur la boîte noire).

    Une différence avec [go_router] : son option [refreshListenable] réévaluait les gardes de la page courante à chaque changement de la session (on était renvoyé à la connexion si l'on se déconnectait sur l'agenda). Le routeur d'[Angular] n'appelle les gardes qu'au moment d'une navigation. C'est pourquoi la déconnexion (plus loin) est suivie d'une navigation vers l'accueil.

// -------------------------------------------------------------------------
// Après la connexion, on renvoie l'utilisateur à la page qu'il voulait
// ouvrir (paramètre ?returnUrl=... déposé par le garde), ou à l'accueil.

import { Component, inject, input, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { Router } from '@angular/router';
import { IonButton, IonCard, IonCardContent, IonInput, IonText } from '@ionic/angular';
import { Session } from '../session';

@Component({
  selector: 'app-ex18-connexion',
  imports: [FormsModule, IonCard, IonCardContent, IonInput, IonButton, IonText],
  templateUrl: './connexion.page.html',
})
export class Connexion {
  // l'adresse demandée, déposée par le garde connexionRequise
  readonly returnUrl = input<string>();

  // les champs du formulaire et l'erreur : des signaux
  readonly login = signal('');
  readonly password = signal('');
  readonly erreur = signal(false);

  private readonly session = inject(Session);
  private readonly router = inject(Router);

  valider(): void {
    if (!this.session.connecter(this.login().trim(), this.password())) {
      this.erreur.set(true);
      return;
    }
    // on n'accepte qu'un chemin INTERNE : il commence par /, mais pas par //
    // (//site.com/... désigne un AUTRE site) - pas de redirection vers un autre site
    const r = this.returnUrl();
    const interne = r !== undefined && r.startsWith('/') && !r.startsWith('//');
    this.router.navigateByUrl(interne ? r : '/ex18');
  }
}
